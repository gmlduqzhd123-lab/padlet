# 연결 안내 검수 · 2026-10-09

후속 배포 완료: 커밋 6ce5de5를 main으로 전송했고 GitHub Pages 배포 성공 및 공개 출처 시험 5개 PASS를 확인했다. 아래 ‘로컬/미배포’ 표현은 배포 요청 전 검수 시점의 기록이다. 현재 상태는 [배포 보고서](DEPLOYMENT_REPORT.md)를 따른다.

사용자 화면의 기존 버튼은 URL만 해석하면서 API 자격·관리자 권한·CORS·첨부에 모두 ‘미검증’을 표시했다. 요청 실패와 검사 미실행을 혼동하는 안내를 수정했다. 이번 변경은 로컬이며 공개 Pages에 배포하지 않았다.

변경 파일: index.html, assets/js/app.js, tests/api.cjs, README.md, PRD.md, TASKS.md, ACCEPTANCE.md, docs/FEASIBILITY.md, 이 보고서.

- ‘주소 확인 · 연결 안내’는 URL만 확인하며 원격 요청을 보내지 않는다. API 패널을 펼치고 키 입력(보드 ID가 없으면 ID 입력)으로 이동한다.
- 키가 없을 때 연결 검사와 가져오기는 요청 없이 ‘검사 안 함’과 다음 행동을 표시한다. 키 없이 CSV/XLSX·첨부 ZIP으로 진행하는 링크를 추가했다.
- 실제 GET 응답을 읽었을 때 현재 출처의 이번 응답 성공만 표시한다. 권한 오류는 NOT_ADMIN/HTTP 403 등 구체적인 오류로 표시한다. 첨부 바이트 확보와 저장은 별도로 남긴다.
- 보드 연결 검사에서도 직접 입력한 보드 ID를 지원한다. 진행 중 다른 API/가져오기/저장 작업을 잠그고 완료 후 해제한다. 키는 요청 시작 시 입력창에서 지운다.
- 게시물 수집 완료·중단을 상단 결과에 반영하며, 더 이상 ‘자동 수집 미구현’이라는 이전 안내를 표시하지 않는다.

시험: Windows / Chrome / Playwright, localhost의 /repo/ 상대경로. `node tests/api.cjs` 27개 PASS, `node tests/run.cjs` 39개 PASS. 실제 키/학생자료 없이 가상 게시물·가상 키·가상 API/CDN 응답만 사용했다. API route 모의 응답 성공은 실제 패들렛 수집 성공이 아니다. 브라우저 스크립트 오류 0, 키 없는 경로 원격 요청 0, 로컬 자료 처리 원격 요청 0. ZIP은 시험 도구로 다운로드 후 독립 해제했다. 최종 시험 FAIL 0.

NOT_RUN: 사용자 API 키/자격/보드 관리자 권한, 실제 Pages 인증 API CORS, 실제 원격 첨부 원본 바이트, OS 폴더 사용자 승인. 이유: 승인된 실계정/키/비식별 보드가 제공되지 않음. 키를 채팅이나 저장소에 올리지 않고 본인 브라우저에서 시험한다.

실행: 변경 파일을 Pages에 반영한 뒤 링크 → 주소 확인 → 키 입력 → 보드 연결 검사. 검사는 키를 소비하므로 게시물 가져오기 전에 다시 입력한다. 키가 없으면 패들렛에서 내보낸 CSV/XLSX와 첨부 ZIP을 가져오고 열 연결 적용 → 자료/원문 확인 → 폴더 또는 ZIP 출력으로 사용한다. 공개 화면 변경에는 이 로컬 변경의 배포가 필요하다.

공식 [인증 문서](https://docs.padlet.dev/reference/authentication)를 2026-10-09 다시 확인했다. API 키, 유료 이용 자격 및 대상 보드 관리자 권한을 요구한다. 링크만으로 인증을 대체하지 않는다.
